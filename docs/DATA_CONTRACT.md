# 数据口径与兼容边界

日期：2026-09-10

## 1. 日志协议

当前适配 `session_meta`、`turn_context`、`event_msg/token_count`、`response_item`、`compacted`。只读取 `rollout-*.jsonl`。Codex 日志不是本项目可控制的稳定接口；未知事件忽略，破损行与超大行明确标注。

参考 OpenAI 协议源与 App Server 文档：

- https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs
- https://developers.openai.com/codex/app-server/

这些链接仅用于追踪协议来源，不代表本程序已对每个版本实测。

## 2. Token

`input + output` 是总数，cached 是 input 子集，reasoning 是 output 子集。累计值按相邻高水位求差；相同累计值不重复计数。

首条累计值和最后请求值一致时，可以归属首个事件；不一致时保存为日期／模型未知基线，不把整段历史装进今日或最后一个模型。后续增量与最后请求不一致时也保守地保留为未归属增量。

计数回退不是必然开启新周期，首版不盲目重置后相加。回退会标记诊断，可能低估回退后的用量。需要真实版本样例后再扩展。

输入、输出未知时不能凭 total 猜构成。上游 total 与输入加输出不一致时保留诊断，以输入加输出展示。

## 3. 父子关系与 Fork

优先读取本地 `thread_spawn_edges`，也支持 `session_meta.source.subagent.thread_spawn.parent_thread_id`。缺少父节点的子代理独立显示，不根据最近写入文件猜关系。

聚合递归到全部已识别后代，集合去重并处理循环。循环数据仍需要人工核对。

对同一会话的复制文件去重；存在明确 Fork 祖先时，去掉相同历史事件。祖先不可见、计数被重写或协议未提供关系时不能保证完全还原，必须保留提示。

## 4. 时间窗口

今日使用电脑本地自然日起点，近 7 天包含今天和之前 6 个自然日，近 30 天同理。用事件时间归属，不使用文件最后修改时间。缺少时间的基线只出现在累计，不出现在日统计。

任务列表固定展示累计父子拆分，与概览和 Skills 的时间窗口不同，界面已单独标注。

## 5. Skills

默认只发现本地 `SKILL.md`，不把“文件存在”当成“Codex 当前已启用”。项目从选择的 cwd 向上到仓库根发现 `.agents/skills`；支持额外根目录，不扫描整个插件缓存冒充真实目录。

支持常见 YAML frontmatter：name、单行或块状 description；不是完整 YAML/TOML 解析器。有效目录状态可从已有 `skills/list` 响应离线导入；只表示当时状态。它不证明历史会话里启用了相同 Skill。一个物理目录在多个 cwd 中不同状态会标记未知。

证据保留四类：

- 用户文本中的 `$skill-name`：明确提及，不一定是执行指令，可能是举例。
- 简单 `cat/sed/head/tail` 或 read_file 读取 `SKILL.md`：尝试读取。
- 对应 call_id 输出有明确成功退出状态：读取返回成功，不证明全文或执行效果。
- 助手文本中的 Skill 标记：自述证据，不作为成功执行。

首版对复合 Shell、管道、封装脚本等保持保守，可能漏报。无法确认退出状态时不推断成功。仅名字匹配时，多个同名目录不重复分配；有精确路径时按路径关联。没有出现在当前目录的历史 Skill 不会自动补全成已安装项。

每个 session/turn/Skill/证据类型去重；未提供稳定 turn_id 的旧日志采用本地回合编号，属于兼容近似。统计不能用于可靠判断漏触发／误触发率，不作自动删除或开启建议。

目录 Token 采用字符 / 4 启发式，尤其不适合当作中文内容精确计费。Codex 的渐进式加载语义参考： https://developers.openai.com/codex/skills/

## 6. 成本

默认没有真实模型价格。使用本地 PriceBook 的精确模型名匹配，分未缓存输入／缓存输入／输出套单档费率，不还原历史费率。maxInput 限制适用输入窗口，超过则排除，不假设可用同价。

未配置多档长上下文、缓存写入附加费、工具费、服务层级、地区价、订阅额度换算。金额只是用户提供费率下的参考估算，不应当作真实账单。

## 7. 回填与性能

完整行检查点；半行不提交；inode、长度、时间和边界指纹辅助识别重写；超长行流式丢弃后继续恢复。32 MiB / 2 秒预算主要约束逐行扫描，不是整个系统操作的绝对硬实时上限。

目录枚举、SQLite 元数据查询和首次缓存编码仍可能产生额外开销。每轮最多 30,000 个会话文件；单行最多 1 MiB；缓存最大持久化 128 MiB。极大历史尚需进一步性能压测。无变化的日志不会从头重读，无变化缓存不重复写入。

来源删除后移除对应扫描缓存；历史统计依赖你仍保留的本地日志，不代表账户云端的完整历史。
