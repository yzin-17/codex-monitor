# Codex 当前账号额度来源与本机优先刷新 Spec

> 任务标识：codex-local-first-account-refresh
> 日期：2026-09-18
> 状态：三模式本地实现与合成验收完成；真实账户切换和长期运行待独立实机验收
> 对应任务：[2026-09-18-codex-local-first-account-refresh.md](../tasks/2026-09-18-codex-local-first-account-refresh.md)

## 背景与问题

本机 Codex 已能提供当前登录账号的额度，但现有远程账号轮询仍会请求所有已启用账号，且匹配账号只有在远程数据失败或过期时才回退本机。`UsageSnapshot.lastUpdated` 同时承担界面刷新时间，不能证明额度的真实采集时间；稳定化或快速缓存复用旧额度时，若用普通刷新时间替代采集时间，会让旧额度永不过期。

## 目标

- 当前本机身份仍只通过显式绑定与精确 Account ID 匹配确定，不自动绑定。
- 自动刷新跳过具有有效本机额度的当前账号，只远程请求非当前账号，以及本机额度不可用时的当前账号。
- 首次本机刷新完成前，匹配的当前账号保持等待；首次确认不可用或从可用变为不可用时立即远程兜底一次，重复不可用不触发快速连发。
- HUD 与远程账号卡片对匹配的当前账号始终优先展示有效本机额度并标记“本机读取”，同时保留远程 plan、Credits 与远程读取时间。
- 额度真实采集时间贯穿实时读取、快速缓存与稳定化合并，并能按年龄失效。
- 将“额度来源”调整为“本机优先”“仅本机”“仅远程”三种模式；本机统一表示 `app-server → 本地记录`，远程只表示已保存账号凭据发起的官方额度请求。
- HUD 与账号卡片显示最终实际渠道，而不是只显示策略名称。

## 非目标

- 不新增持久化字段或迁移文件，不增加“远程优先”，不改变现有刷新周期、官方请求协议、凭据边界、绑定按钮与 65 秒身份切换稳定期。
- 不自动绑定或切换账号，不使用真实凭据，不把真实账户切换或长期运行纳入本次本地自动化验收。
- 不把内部额度采集时间加入诊断 JSON、命令行快照或其他外部输出。

## 现状与约束

- `CodexAccountsStore` 负责账号、绑定、身份监听、远程请求队列和最多 3 个并发任务；现有任务/队列去重必须保留。
- `UsageViewModel` 发布本机 `UsageSnapshot`，`NotchOverlayController` 已集中订阅发布状态，适合作为本机快照到账号 Store 的接线点。
- 当前工作树包含对话费用预取相关未提交修改，尤其是 `UsageViewModel.swift` 与 `NotchIslandView.swift`；实现只能做兼容的最小增量，不得覆盖或回滚。
- 本机额度有效期为 `max(120 秒, 2 × idleRefreshInterval)`；有效额度必须包含可用 7d，5h 可缺省，且采集时间不得早于最近身份切换。

## 设计方案

### 额度采集时间

`UsageSnapshot` 新增可选 `rateLimitCapturedAt`。新鲜读取使用 `RateLimitSnapshot.capturedAt`；快速缓存继续携带缓存内快照原时间；稳定化从旧快照补额度时同步保留旧采集时间。普通 `lastUpdated` 仍只表示界面快照刷新时间。

### Store 内本机额度状态

`CodexAccountsStore` 维护 `unknown`、`available`、`unavailable` 三态及只读本机额度展示快照。控制器仅在首次本机快照发布后开始同步 `UsageSnapshot` 与 `idleRefreshInterval`，因此启动初始值不会被误判为不可用。

对显式绑定且精确匹配当前身份的账号：

- 身份仍处于 65 秒稳定期，或尚未收到首次本机快照时为 `unknown`；
- 存在 7d、真实采集时间不早于最近身份切换且年龄不超过有效期时为 `available`；
- 首次刷新已完成且上述条件不成立时为 `unavailable`。

非当前、未绑定或身份不匹配账号不受本机抑制，按原周期远程刷新。

### 自动与手动刷新

- “本机优先”下，当前匹配账号为 `unknown` 或 `available` 时不入远程队列，为 `unavailable` 时按现有周期入队；状态首次变为 `unavailable`，或从 `available` 变为 `unavailable` 时立即尝试一次远程兜底，持续不可用时不重复触发即时请求。
- “仅本机”下，当前匹配账号始终不自动请求远程额度，本机不可用时明确显示不可用；已存在或手动取得的远程 plan、Credits 与读取时间仍可展示，但远程额度不接管当前账号。
- “仅远程”下，当前匹配账号忽略本机额度并按现有周期请求远程接口，不等待首次本机额度刷新；未绑定或远程监测关闭时明确不可用，不自动绑定、开启监测或回退本机。
- 非当前账号在三种模式下均照常入队。
- 身份切换立即废弃旧本机状态；原当前账号成为非当前账号后立即进入远程刷新，新当前账号等待匹配的新本机额度。
- `interactive: true` 始终绕过本机抑制，但继续受现有活动任务与排队去重约束。

### 统一展示数据

Store 为每个账号生成统一展示数据：策略、实际渠道、额度窗口与采集时间，以及可并存的远程 plan、Credits、远程读取时间、错误和刷新状态。账号卡片的实际渠道区分“本机读取 · 实时接口”“本机读取 · 本地记录”“远程读取 · 自动兜底”和“远程读取”；HUD 使用对应短标识“本机·实时”“本机·记录”“远程·兜底”“远程”，避免挤占额度指标。两处消费同一判定，避免语义漂移。

### 设置与兼容

继续复用 `rateLimitSource` 持久化键。旧 `appServerFirst` 映射为“本机优先”，旧 `localFilesOnly` 映射为“仅本机”；默认值为“本机优先”。“仅本机”恢复 `app-server` 优先、本地记录回退，但不启用当前账号自动远程兜底。

## 对外行为或接口变化

- `UsageSnapshot.rateLimitCapturedAt` 为可选内部调度字段，不进入外部序列化输出。
- `UsageSnapshot` 增加可选的实际本机额度渠道字段，仅供内部展示和调度，不进入外部序列化输出。
- `CodexAccountsStore` 的本机快照同步入口同时接收三模式策略，并统一自动刷新判定与账号展示数据。
- 用户可见来源标识显示最终实际渠道；远程 plan、Credits 与远程读取时间可与本机额度同时显示。

## 数据、状态或兼容性影响

无新增持久化 Schema、UserDefaults 键或 Keychain 变更。旧设置值按兼容映射读取，旧账号配置继续解码。状态仅存在于当前进程，重启后按当前策略重新建立。

## 测试策略

### 关键可观察行为

- 单账号本机有效时自动请求数为 0；多账号仅请求非当前账号；未绑定账号正常请求。
- 本机缺失或过期时立即兜底一次，持续不可用不会因本机快照重复同步而快速连发。
- 身份切换后旧账号立即恢复远程刷新，新账号等待新本机额度；手动刷新全部目标且保持去重。
- 匹配当前账号即使已有新鲜远程额度也展示本机额度；本机不可用才用远程额度。
- 本机额度与远程 plan、Credits、远程读取时间在卡片中并存。
- 三模式分别执行本机优先兜底、严格仅本机和严格仅远程；未绑定与监测关闭时不违反“仅远程”语义。
- app-server 成功与失败回退本地记录均保留准确的实际渠道。

### 测试层级与证据边界

- Swift 定向测试覆盖状态机、请求计数/去重、展示选择、采集时间实时/缓存/稳定化传播。
- 原生截图测试使用合成账号验证“本机读取”和远程专属字段并存；不证明真实账号或官方端点可用。
- 完整 `scripts/test.sh`、原生截图测试、`scripts/build.sh` 与 `git diff --check` 证明当前未提交工作树的本地回归和构建，不替代真实账户切换及长期运行验收。

## 风险与备选方案

- 快速刷新可能不断生成新界面时间；必须只用 `rateLimitCapturedAt` 判断额度年龄。
- 身份切换与本机快照到达可能交错；通过切换时间、65 秒稳定期和采集时间下界拒绝旧快照。
- 即时兜底与周期轮询可能相遇；复用现有任务/队列去重，不建立第二套请求执行器。

## 验收标准

- AC1：`UsageSnapshot` 保留真实额度采集时间，实时读取、快速缓存、失败缓存和稳定化合并均不把普通刷新时间冒充为采集时间，且该字段不进入诊断 JSON。
- AC2：Store 正确维护 `unknown`、`available`、`unavailable`，有效性同时满足当前身份、显式精确绑定、有效 7d、身份切换时间下界和动态年龄上限，5h 可缺省。
- AC3：自动轮询、本机不可用即时兜底、身份切换和重复不可用抑制符合规则；手动刷新绕过抑制并保留请求去重。
- AC4：HUD 与远程账号卡片统一执行本机优先；“本机读取”、本机额度与远程 plan、Credits、远程读取时间按约定展示。
- AC5：要求的定向测试、完整测试、原生截图测试、构建与 diff 检查通过；真实账户切换和长期运行明确保留为独立实机验收。
- AC6：设置提供“本机优先”“仅本机”“仅远程”三种模式，兼容旧值，并按策略统一控制自动请求、HUD 和账号卡片展示。
- AC7：实际额度渠道准确传播和展示，且 provenance 与采集时间均不进入诊断 JSON 等外部输出。
